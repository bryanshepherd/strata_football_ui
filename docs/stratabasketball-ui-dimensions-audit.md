# StrataBasketball UI Dimensions Audit

## Executive summary

The main StrataBasketball scorer shell is implemented in `/Users/bryanshepherd/strata-basketball-ui/src/App.jsx`. The five primary scorer sections are laid out inside `BasketballGame` as a column flex container: Scoreboard on top, a three-column middle row, and Input Assistant on the bottom. The middle row uses horizontal flex placement: Stats at `20%`, Input at `65%`, and Event Log at `15%`.

No fixed pixel heights are defined for the five primary sections. Height is derived from content, padding, and the `min-h-screen flex flex-col` / `flex-1` relationship in the scorer shell. Stats, Input, and Event Log each set `h-full`; their effective height depends on the middle row's used height. Because the shell uses `min-h-screen` rather than `h-screen`, content can make the page taller than the viewport, and internal scroll containers only become meaningful when the browser has a constrained used height for the middle row.

There are no screen-size responsive breakpoint classes (`sm:`, `md:`, `lg:`, etc.) or non-print media queries affecting this scorer layout in the audited files. The only custom width classes are `.w-main-content { width: 65%; }` and `.w-sidebar-right { width: 15%; }`; the Stats width uses Tailwind's standard `w-1/5` utility. The only `@media` block in `src/index.css` is print-specific and targets quick-box report classes, not the scorer shell.

## Dynamic sizing and uncertainty notes

- The five primary sections do not have explicit fixed heights. The browser derives heights from content and the flex column: Scoreboard and Input Assistant consume content height, and the middle row receives remaining available height through `flex-1`.
- Because the scorer shell is `min-h-screen`, not `h-screen`, the middle row is not strictly capped to the viewport. If section content exceeds the available space, the document can grow and page-level scrolling may occur.
- `h-full` on Stats, Input, and Event Log depends on the parent column having a definite used height. In practice this comes from the middle flex row's used height, but it is not a fixed CSS value.
- Stats has the most dynamic sizing: it first attempts to scale content down to avoid vertical overflow, then still allows vertical scrolling on the container.
- Input's internal roster columns use `w-[14%] min-w-[140px]`, so on narrow layouts the two `min-w` constraints plus `gap-3` reduce the remaining center width. There is no responsive breakpoint that stacks or hides those columns.
- Event Log's `15%` width has no minimum width; its header controls and play rows determine whether content overflows horizontally.
- Input Assistant status chips wrap. Additional FTP/sync chips increase the assistant height and reduce the remaining flex space available to the middle row.
- The only `@media` block found in `src/index.css` is print-specific and scoped to quick-box report classes, not the scorer UI sections audited here.
